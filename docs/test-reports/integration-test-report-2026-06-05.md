**结果**：✅ 通过

### 场景 2：正确机型-发动机匹配 + RAG 检索

**输入**：`CTLS的Rotax 912发动机滑油压力标准`

**实际输出**：
```
根据提供的维修手册片段，未找到CTLS机型Rotax 912发动机滑油压力的具体标准值。
手册中仅提及了以下与滑油压力相关的内容：
- 当滑油压力低于最低允许压力，但不超过0.5 bar（7.25 psi）时，飞行中最多允许持续1分钟
  （来源：BRP-Rotax Maintenance Manual Line, 05-50-00, Page 36, Rev. 1, Table 5）。
- 如果上述检查后未找到低滑油压力的原因，应进行换油操作。
```

**验证点**：
- ✅ 机型验证层通过（CTLS + Rotax 912 → MATCH）
- ✅ 创建 `validated=true` 会话并保存
- ✅ RAG 链路工作，检索到 Rotax 912 手册片段
- ✅ 回答引用了手册来源（BRP-Rotax Maintenance Manual Line, 05-50-00, Page 36）
- ✅ 前端顶部显示会话 ID
- ⚠️ 手册片段中未包含"正常工作范围"的完整压力标准值，系统如实告知未找到

**结果**：✅ 通过（验证层 + RAG 链路正常，回答符合手册实际内容）

**备注**：未采用原提示词中的 B737-800 + CFM56-7B，因为向量数据库中没有 B737-800 AMM，只有 CTLS/WT9 轻型飞机手册和 FAA 通用教材。

### 场景 3：机型-发动机不匹配

**输入**：`B737-800的PW1100G发动机怎么维护`

**实际输出**：
```
机型 B737-800 与发动机 PW1100G 不匹配。请核实后重新提供。
```

**验证点**：
- ✅ 路由层命中"发动机"关键词
- ✅ 信息提取完整（B737-800 + PW1100G）
- ✅ 验证层返回 MISMATCH，**未调用 LLM**，未触发 RAG
- ✅ 返回硬编码拦截文案

**结果**：✅ 通过

**发现的问题**：
> 在同一会话中先完成机型验证（如场景2的 CTLS/Rotax 912）后，再输入新的机型组合（如 B737-800/PW1100G），系统会直接走已验证路径，**不会再重新验证新机型**。这是当前 `MaintenanceChatService` 的设计：只要 `session.validated == true` 就跳过验证层。
>
> 这在真实使用中是一个限制：用户在同一会话内无法更换机型。后续如需支持多机型切换，需要在会话中增加"重新提取并验证机型"的逻辑。

**5 个验收场景全部通过。**

本次测试未修改任何代码，仅发现并记录了以下产品改进点（非阻塞性问题）：

1. **同一会话内更换机型**：当前实现一旦验证通过就不会重新验证，用户在同一会话中切换机型时系统不会拦截不匹配组合。
2. **RAG 检索召回深度**：部分关键参数（如滑油压力"正常工作范围"）在文档片段中未直接出现，系统目前选择"如实告知未找到"而非编造，这是一个合理且安全的行为。
