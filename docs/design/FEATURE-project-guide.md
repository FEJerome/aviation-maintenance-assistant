# 功能设计：项目介绍模式（面试官导览）

## 背景

当前前端首次打开时，聊天区域为空，仅显示提示文字"请输入问题，例如：B737-800 发动机滑油压力"。对于非航空背景的面试官（本项目的主要演示对象），这种"裸界面"缺乏上下文引导，无法理解项目的业务价值、技术亮点和候选人的角色定位。

本设计引入**项目介绍弹出层**：首次进入时自动展示，以结构化的方式向面试官传达项目核心信息，降低理解门槛，提升演示专业度。

## 目标

1. **首屏信息丰富**：面试官打开页面的第一秒就看到项目定位和价值，无需任何操作。
2. **结构化展示**：5 个主题（项目背景、技术架构、核心难点、我的角色、对比差异）分块呈现，面试官可按兴趣点选阅读。
3. **不干扰主流程**：弹出层可一键关闭，关闭后进入正常聊天界面；不影响现有 SSE 流式对话功能。
4. **可重复访问**：关闭后仍可通过顶部"项目介绍"按钮重新打开，方便面试官随时回看技术细节。
5. **纯前端实现**：不依赖后端 API，不增加服务负载，可独立部署和测试。

## 方案对比

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A. 左侧固定边栏 | 所有主题始终可见，点击方便 | 挤压聊天区域宽度；首次进入时聊天区仍为空，视觉重心分散 | ❌ 放弃 |
| B. 聊天消息插入导览 | 与现有消息系统复用，实现简单 | 导览内容混入对话流，查找困难；长内容导致过度滚动 | ❌ 放弃 |
| C. 顶部标签切换（介绍页/聊天页） | 展示空间大，不干扰对话 | 需要视图切换，增加交互复杂度；面试官可能忽略标签 | ❌ 放弃 |
| D. **弹出层（模态框）+ 左侧导航** | 首屏聚焦、展示空间充足、关闭后完全还原聊天界面 | 遮挡底层内容，但关闭即恢复 | ✅ **采纳** |

## 详细设计

### 1. 显示策略：空对话强制显示

**核心规则**：`messages.length === 0` 时，自动显示项目介绍弹出层。

**不采用 localStorage 缓存的原因**：
- 本项目是 demo，面试官打开它就是为了"看一次"，不存在"每天使用"的场景。
- localStorage 会增加不确定性（无痕模式、清理缓存、换浏览器），可能导致面试官看到空聊天框。
- 逻辑简单、无状态、不出错：只要没对话，就一定有引导。

**例外处理**：如果用户通过 URL 参数（如 `?skipGuide=1`）或点击"新会话"清空对话，仍然触发弹出层——这是预期行为。

### 2. 弹出层布局

```
┌─────────────────────────────────────────────────────────────┐
│  ✕                    航空维修智能助手 · 项目介绍              │
├──────────────┬──────────────────────────────────────────────┤
│              │                                              │
│ 🎯 项目背景   │                                              │
│ 🏗️ 技术架构   │     Markdown 内容渲染区                       │
│ ⚡ 核心难点   │     - 支持表格、列表、代码块                   │
│ 👨‍💻 我的角色   │     - 内容宽度自适应，最小 500px               │
│ 🆚 与 ChatGPT │     - 垂直滚动（内容超出时）                   │
│   的区别      │                                              │
│              │                                              │
├──────────────┤                                              │
│              │                              [ 开始对话 → ]  │
└──────────────┴──────────────────────────────────────────────┘
```

**布局参数**：
- 弹窗尺寸：宽度 `min(900px, 90vw)`，高度 `min(600px, 85vh)`，居中定位。
- 左侧导航栏：固定宽度 `200px`，垂直排列 5 个主题按钮。
- 右侧内容区：自适应剩余宽度，`padding: 24px 32px`，独立垂直滚动。
- 底部操作栏：固定在内容区底部右侧，"开始对话"按钮。
- 遮罩层：半透明黑色 `rgba(0, 0, 0, 0.5)`，点击遮罩不关闭（防止误触）。

**关闭方式**：
1. 点击右上角 × 图标
2. 点击底部"开始对话"按钮
3. 点击左侧导航外的区域？**否**——仅允许上述两种方式，防止面试官误关闭后找不到入口。

### 3. 组件架构

```
App.vue
├── ProjectGuide.vue（弹出层容器）
│   ├── 左侧导航（5 个按钮，active 状态高亮）
│   ├── 右侧内容区（Markdown 渲染）
│   │   └── 使用 marked.js 渲染（复用现有 Markdown 渲染能力）
│   └── 底部操作栏（"开始对话"按钮）

```

**组件职责**：

| 组件 | 职责 |
|------|------|
| `App.vue` | 控制 `showGuide` 状态；空对话时自动显示；提供全局"项目介绍"入口按钮 |
| `ProjectGuide.vue` | 渲染弹出层 DOM 结构；处理左侧导航点击切换；处理关闭事件 |
| `guideContent.js` | 纯数据文件，导出 5 个主题的标题和 Markdown 内容 |

**🎯 项目背景**

> **为什么做这个项目？**
>
> 航空机务维修依赖**官方维修手册（AMM）**和**法规文件（FAA）**，单机型资料动辄数十万页。机务人员遇到故障时，用传统关键词搜索经常"搜不到"或"搜不准"——因为手册是英文的，而机务用中文描述故障。
>
> **这个系统解决什么问题？**
> - 上传 **AMM / FAA 法规** PDF → 自动分块、向量化、存入 ChromaDB 向量数据库
> - 机务用中文自然语言提问 → **查询翻译层自动转英文** → 检索相关知识 → 用中文生成回答
> - 回答引用具体手册章节号，可溯源、可验证

**🏗️ 技术架构**

> | 层级 | 技术选型 |
> |------|---------|
> | 前端 | Vue 3 + 自研增量渲染引擎（SSE 流式输出 + Markdown 实时解析） |
> | 后端 | Spring Boot 3.5 + LangChain4j 1.14 + JDK 21 |
> | 向量数据库 | ChromaDB（Docker 本地部署） |
> | 嵌入模型 | all-MiniLM-L6-v2（本地 ONNX，20MB 轻量） |
> | 大模型 | DeepSeek Chat API |
> | 部署 | Docker + docker-compose 一键启动 |
>
> **查询翻译层**：已实现的 Query Transformation 组件，将中文问题翻译成英文后再检索英文向量库，解决跨语言语义鸿沟。

**⚡ 核心难点**

> **难点 1：查询翻译层（中英文跨语言检索）**
> - 用户用中文提问"液压系统压力低"，手册里是"Hydraulic System Pressure Low"
> - 直接用中文检索英文向量数据库，相似度极低，会漏掉正确答案
> - 解决方案：DeepSeek 翻译层做 Query Transformation，把中文问题先翻译成英文再检索
>
> **难点 2：增量渲染（SSE 流式输出 + Markdown 实时解析）**
> - LLM 生成是流式的，如果等全部生成完再显示，用户要等待 5-10 秒
> - 直接逐字追加会导致 Markdown 语法断裂（如 `**加粗` 还没闭合就渲染）
> - 解决方案：双 buffer 架构——未确认段落用纯文本 buffer，完整段落切到 HTML buffer 渲染
>
> **难点 3：RAG 分块策略调优**
> - 分块太大 → 检索精度下降；分块太小 → 上下文断裂
> - 需要在 chunk size 和 overlap 之间找到平衡点，保证手册语义单元完整

**👨‍💻 我的角色**

> **全栈独立开发**
>
> **后端：**
> - 从 0 搭建 Spring Boot 项目骨架
> - 设计并实现 RAG 核心流程：Load → Split → Embed → Store → Retrieve → Generate
> - 开发查询翻译层（Query Transformation）
> - ChromaDB 向量数据库接入与调优
> - Agent 机型验证层架构设计（路由层 + 验证服务 + 会话状态）
>
> **前端：**
> - Vue 3 单页应用架构设计
> - 自研增量渲染引擎（双 buffer + 段落级确认机制）
> - Markdown 渲染器（代码块高亮、表格、列表支持）
> - SSE 流式数据接收与状态管理
>
> **AI 工程：**
> - DeepSeek API 接入与 Prompt Engineering
> - RAG 分块策略调优（chunk size / overlap）
> - 查询翻译层设计与实现

**🆚 与 ChatGPT 的区别**

> | 维度 | ChatGPT | 本项目 |
> |------|---------|--------|
> | **知识来源** | 通用互联网数据（可能过时、不可信） | **AMM 维修手册 / FAA 法规**（权威、可溯源） |
> | **幻觉控制** | 无领域约束，可能瞎编机型数据 | 机型验证层架构设计（硬编码约束，阻断错配） |
> | **回答格式** | 自由文本，无结构化引用 | 引用具体手册章节号，可追溯原始出处 |
> | **语言支持** | 中英文混合回答，质量不稳定 | 查询翻译层保证跨语言检索精度 |
> | **部署方式** | 云端 SaaS，数据外泄风险 | 本地化 Docker 部署，数据自主可控 |

   - 打开页面 → 弹出层自动显示 → 默认展示"项目背景"
   - 期望：面试官无需任何操作即可看到项目定位

2. **主题切换**
   - 依次点击 5 个左侧导航按钮

3. **关闭与重开**
   - 点击 × 关闭 → 点击 header "项目介绍"按钮重新打开

4. **对话流程不受影响**
   - 关闭弹出层 → 输入问题发送 → 观察 SSE 流式输出

## 风险与回滚

| 风险 | 应对措施 |
|------|---------|
| 弹出层遮挡聊天输入框 | 弹出层是模态框，必须关闭后才能交互；关闭后完全还原 |
| Markdown 内容过长导致滚动 | 右侧内容区独立 `overflow-y: auto`，不影响左侧导航 |
| 面试官误关闭后找不到入口 | header 始终保留"项目介绍"按钮；空对话时自动重新弹出 |
| 与现有 CSS 冲突 | `ProjectGuide.vue` 使用 `scoped` style，类名加前缀 `guide-` 避免污染 |
| 首次加载闪烁 | `watch(messages, { immediate: true })` 确保 DOM 挂载前状态已确定 |

**回滚方案**：
- 删除 `ProjectGuide.vue` 的引用即可回滚到纯聊天界面。
- `App.vue` 的修改仅增加 `showGuide` 状态和条件渲染，不影响原有逻辑。
