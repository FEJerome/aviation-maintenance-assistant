# ADR-007：定位转型 — 从公共托管 PoC 到自托管工具包

- **状态**：Accepted
- **日期**：2026-11-12
- **决策者**：马昊宇（项目作者）

---

## 背景

项目最初以"公共托管 PoC + 在线演示地址"为目标形态：部署到云服务器、绑定域名、供访客直接体验问答。在推进过程中，这一形态暴露出三类结构性问题：

1. **版权与合规风险**：系统价值依赖真实维修手册语料，但手册受版权保护，不能随仓库分发，也不适合在公共实例上代为托管。公共演示要么没有真语料（演示失真），要么游走在授权边界上（不可接受）。
2. **成本与安全风险**：公共在线问答意味着 API Key 由部署方承担、暴露在开放网络中，需要持续对抗刷量与滥用；这与"演示项目"的资源预算不匹配。
3. **定位模糊**：面向访客优化（在线体验、引导弹窗、演示话术）冲淡了系统真正的工程价值——确定性与概率分离的控制流、可追溯的 RAG 链路、领域验证层。

候选定位：

1. **维持公共托管 PoC**（现状延续）
2. **转型为可自托管的垂直 RAG 工具包**，内置机务维修参考实现
3. **转型为 SaaS 产品原型**（多租户、账号体系）

---

## 考虑的选项

### 选项 A：维持公共托管 PoC

**优势**：
- 零改造成本，访客点开即用，传播路径最短

**劣势**：
- 手册版权无解：真实语料不能公开托管，演示只能停留在"玩具语料"层面
- 长期承担 LLM 账单与滥用风险；限流只能缓解不能根除
- 维护一个公共在线服务与项目"工程能力展示"的核心目的不成正比

### 选项 B：自托管垂直 RAG 工具包（采纳）

**优势**：
- 版权边界清晰：仓库不附带任何手册，用户自带合法获取的文档（BYOD），责任归属明确
- 成本归属清晰：用户自带 OpenAI 兼容模型与密钥（BYOK），部署方不再为他人流量买单
- 工程价值前置：评测（golden-set）、只读 MCP、配置契约都可以作为可复现的工件交付，而不是藏在某个在线实例背后
- 与既有技术决策完全兼容：ChromaDB 本地持久化（[ADR-002](ADR-002-chromadb-over-others.md)）本来就是"零环境差异"的自托管友好选型；DeepSeek 走 OpenAI 兼容协议（[ADR-003](ADR-003-deepseek-over-dashscope.md)）天然支持端点可替换

**劣势**：
- 体验门槛提高：访客需要自己部署、自己准备 Key 和文档，传播性下降
- 需要补齐文档契约（配置、MCP、评测）才能让"工具包"成立，有一次性文档成本

### 选项 C：SaaS 产品原型

**优势**：
- 商业化叙事最完整

**劣势**：
- 需要账号体系、多租户、计费、运维体系，工作量远超当前项目周期
- 同样无法绕过手册授权问题
- 与项目目标（展示工程能力、可复现交付）偏离

---

## 决策

**采纳选项 B：转型为可自托管的垂直 RAG 工具包，内置机务维修参考实现。**

具体含义：

- **用户自带模型（BYOK）**：任意 OpenAI 兼容端点（base_url / api_key / model）。当前代码默认 DeepSeek；通用化配置是规划中的目标契约（见 [docs/CONFIGURATION.md](../CONFIGURATION.md)）。
- **用户自带文档（BYOD）**：仓库不分发任何手册；快速开始示例使用完全自写的合成语料。
- **首版不做公共实时问答**：移除在线演示地址承诺，部署文档收敛为自托管场景。
- **交付物转向可复现工件**：只读 MCP 契约（[docs/MCP.md](../MCP.md)）、golden-set 评测 schema 与说明（[evals/aviation/](../../evals/aviation/)）作为 planned 工件先行冻结契约。
- **不做**：复杂插件系统、更换实现语言、完整前端 i18n（首版）。

---

## 后果

### 积极影响

- 版权、成本、安全三类结构性风险一次性出清，且不需要牺牲核心功能
- 文档体系从"演示导向"转为"契约导向"：CONFIGURATION / MCP / evals 三份契约可以先行评审，再按规划里程碑落地实现
- 既有 ADR 决策全部保持有效，无返工

### 消极影响 / trade-off

- 失去"点开即用"的传播优势；README 必须用清晰的快速开始和合成示例补偿上手成本
- "planned"状态的契约（MCP、评测）在短期内是承诺而非能力，文档中必须始终明确标注，避免误导使用者
- 机型匹配表、会话存储等演示期简化（硬编码、内存实现）在自托管语境下依然存在，需要在限制说明中保持诚实
